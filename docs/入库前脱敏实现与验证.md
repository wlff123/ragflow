# Presidio 入库前脱敏：初版实现与验证

## 1. 实现范围

特性分支：`feature/presidio-ingress-redaction`。基于 RAGFlow v0.27.2 源码提交 `a024bea0cd93f39e6652a42bf84dd20c55bc560b`，使用 Presidio Analyzer / Anonymizer **2.2.364**。

本版用于**独立的 Python 后端验证实例**，默认关闭。开启后，该实例的所有知识库统一执行入库前脱敏，不提供用户自行跳过的开关。

| 项目 | 本版行为 |
| --- | --- |
| TXT | 严格按 UTF-8 解码，替换命中内容后入库 |
| Markdown | 提取正文与代码块为 TXT；删除链接地址；遇到图片、HTML 或文件头元数据则拒绝 |
| CSV | 表头、单元格逐一处理，保留行列结构；公式样式单元格加单引号 |
| ZIP | 安全解包后逐文件处理上述格式，全部预处理成功后再保存；每次请求最多 5 个子文件，详见 [ZIP 批量入库设计与验证](ZIP批量入库设计与验证.md) |
| 识别范围 | 中国大陆手机号、18 位身份证样式、邮箱、明确格式的密钥、配置的业务敏感词 |
| 替换方式 | 统一为 `[已剔除]`，不保存原值映射；重叠命中合并处理 |
| 文件名 | 使用随机名称，原文件名、原目录不进入文档与文件记录 |
| 凭证 | 服务端 HMAC 签名，绑定租户、知识库、文档、文件名、输出哈希、策略版本和命中统计 |
| 异常 | 规则初始化失败、格式不支持、超限或凭证无效时拒绝处理，不回退为原文入库 |

规则版本为 `rules-v3-presidio-2.2.364`。手机号支持连续数字及 `138-0013-8000`、`138 0013 8000` 写法；密钥规则支持 JSON 键名、单／双引号及带空格的完整值，引号未闭合时拒绝文件。识别器通过 Presidio 公开接口扩展，每条规则超时 1 秒即拒绝处理，不接受部分识别结果。

不需要额外配置 LLM 或下载 NLP 模型。这里使用 Presidio 的规则识别能力；**未实现自由文本中的中文人名、地址识别，也不能据此保证识别所有敏感信息**。业务规则需要用企业样本确认。

## 2. 接入位置

```mermaid
flowchart LR
    A[原生上传界面 / 上传 API] --> Z[ZIP 安全解包；普通文件直接传递]
    Z --> B[内存中校验、正文提取、Presidio 脱敏]
    B --> C[写入并回读核验安全文件]
    C --> D[事务写入文档、文件关联、脱敏凭证]
    D --> E[解析入队前核验]
    E --> F[工作进程再次核验]
    F --> G[RAGFlow 原有切片、向量化、索引与检索]
```

- `common/enterprise_redaction/`：独立的策略、规则、格式处理、文本检查和签名，不依赖 RAGFlow 路由或数据模型。
- `api/utils/redaction_guard.py`：HTTP 入口允许名单、知识库配置写入检查和固定错误响应。
- `api/db/services/redaction_service.py`：适配 RAGFlow 的对象存储与数据库；新增 `redaction_record` 表，只保存签名凭证和统计。
- `FileService.upload_document`：在首次存储前完成整批预处理。普通上传与脱敏上传共用函数内的一段发布事务，复用文档创建与文件关联方法；脱敏模式只追加凭证写入。
- API、任务入队和工作进程：增加校验，防止无凭证文件、跨租户复用或文件被替换后继续解析。
- Docker 入口：脱敏模式限定 Python 后端，关闭连接器同步，拒绝同时启动 Go/混合后端、Admin 或 MCP 服务。

数据库事务失败会撤销关联记录和计数，并尝试删除已经脱敏的对象。若进程在对象写入后意外退出，可能留下**没有文档记录的脱敏对象**，不会自动入队；后续可按未关联对象清理。对象存储与数据库之间没有分布式事务。

通过原生文档／知识库删除入口删除文档时，凭证随文档在同一事务内清理；关闭脱敏开关后删除也执行清理。

## 3. 首版关闭的入口

未适配的写入端点由服务端统一返回 403，包括文件管理上传、文件转知识库、网页导入、空白文档、连接器、手工切片、文档改名和元数据编辑、Wiki 编辑、工作流调试上传及旧版写入 API。未列入允许名单的新写入 API 也会被拦截。

保留账号登录注册、模型配置、知识库基本配置、本地文档上传、解析、删除、下载、查看切片和检索。用户账号与模型凭据不属于文档脱敏范围。

知识库创建、更新在登录认证通过后、写入前检查请求的文本字段（含嵌套配置的键和值），命中则拒绝整次写入，不自动修改配置含义。未登录请求不执行脱敏检查。上传和解析核验还会检查数据库中的解析配置，防止元数据示例或其他配置文本绕过正文脱敏。检查范围仍以本版规则和业务词表为准。

本版未修改前端按钮：不支持的操作仍可能显示，但服务端会明确拒绝。完整的前端隐藏与脱敏状态展示留待后续版本。库级编译、图谱/Wiki 生成、工作流编排入口也未开放；现有数据管道的文档执行入口有凭证校验，但尚不能视为所有工作流组件已适配。

文件限制：单文件 2 MiB、20 万字符，一次最多 5 个文件；每个 Python 进程最多同时预处理 2 个批次。CSV 另限制 1 万行、256 列、2 万单元格。超限直接拒绝，不截断后入库。

每次文本识别中，每类规则最多命中 200 次；当前最多五类规则，进入 Presidio 去重和替换的结果最多 1,000 条。超限返回 `REDACTION_MATCH_LIMIT`，整批上传不落库；CSV 按单元格识别。此限制用于控制正则扫描之后的处理量，敏感内容密集的文件需要先拆分再上传。

## 4. 配置与运行

先使用与上述源码提交匹配的 Python 3.13 RAGFlow 环境，在**新的数据库、对象存储、索引和 Redis 数据空间**中验证。

安装可选依赖：

```bash
uv sync --locked --extra redaction
```

按 `conf/redaction_policy.example.json` 配置业务敏感词。格式固定为：

```json
{"business_terms": ["星桥机密项目"]}
```

API 与所有 Python 工作进程使用相同的环境变量：

```bash
API_PROXY_SCHEME=python
RAGFLOW_REDACTION_ENABLED=1
RAGFLOW_REDACTION_ISOLATED=1
RAGFLOW_REDACTION_POLICY=/ragflow/conf/redaction_policy.example.json
RAGFLOW_REDACTION_HMAC_KEY=<生成的至少32字节随机密钥的十六进制形式>
```

密钥可用 `python -c 'import secrets; print(secrets.token_hex(32))'` 生成，放入受限的部署配置，勿提交到 Git。`RAGFLOW_REDACTION_ISOLATED=1` 表示部署者确认使用了独立数据空间；程序不能仅凭这个变量判断 Elasticsearch 或存储桶是否曾存过其他数据。

启动会检查现有文档的凭证，以及文件关联是否符合要求。存在旧原文、凭证缺失、密钥或策略变化时拒绝启动。初版不做旧库迁移，也不支持在线切换策略；修改规则后应另建验证实例重新导入。

本轮 v3 修正不沿用 v2 凭证。API 与工作进程应使用同一版本，使用新数据空间重新导入测试文件，不能只更新 API 后继续消费旧任务。

Presidio 引入了 `cryptography 48.0.1`，相应升级 `alibabacloud-tea-openapi`、`darabonba-core`；完整依赖变更已记录在 `uv.lock`。不要在现有业务容器中直接覆盖安装。

## 5. 可重复验证

不依赖外部服务的测试：

```bash
python -m pytest test/redaction -q
```

覆盖规则识别与超时、引号密钥、格式化手机号、文件转换、签名核验、HTTP 配置拦截、配置绕过、上传与删除事务回滚，以及开关关闭后的普通上传行为。数据库测试使用 SQLite，存储使用可检查的替身；生产服务函数和模型字段从当前源码加载执行，SQLite 测试跳过 `FOR UPDATE`，不代替 MySQL 行锁或完整服务验证。

实际服务验证脚本：

```bash
PYTHONPATH=. python test/redaction/live_smoke.py \
  --base-url http://127.0.0.1:9380 \
  --embedding-url http://<本地Embedding服务>/v1 \
  --embedding-model <模型名称> \
  --output /tmp/redaction-e2e.json
```

该脚本会创建测试账号、知识库和三个合成文档，验证原生 HTTP 上传、下载、绕过入口拦截、实际工作进程解析、切片和检索，保留结果用于审核。只能对独立的脱敏验证实例执行。

同一环境可继续运行完整性验证，核验实际数据库、对象哈希和凭证，并在替换测试文件后检查解析请求是否被拒绝；脚本在 `finally` 中恢复脱敏文件：

```bash
PYTHONPATH=. python test/redaction/live_integrity.py \
  --report /tmp/redaction-e2e.json --base-url http://127.0.0.1:9380
```

## 6. 升级与下一步

升级 RAGFlow 时，优先核对上传、解析入队、工作进程、路由名称和数据模型这几个接入点，并重跑上述测试。独立脱敏模块通常无需随 RAGFlow 的业务代码一起改写；接口允许名单采用默认拒绝，新版新增接口需要明确评估后开放。

后续范围：PDF/DOCX/OCR、多格式安全副本、中文实体模型、连接器更新与重试、文档覆盖、前端状态展示、库级编译和工作流组件的安全边界，以及企业样本上的漏检/误删评估。初版不能直接作为这些能力已完成的依据。
