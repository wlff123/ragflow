# ZIP 批量入库设计与验证

## 1. 目标与接入方式

基于 `feature/presidio-ingress-redaction` 的 `01ff977` 增加两种能力：

- 普通模式：ZIP 解包后，每个文件成为知识库中的独立文档。
- 脱敏模式：ZIP 解包后逐文件调用现有 Presidio 处理，全部预处理成功后才保存脱敏文件及凭据。

本次实现针对当前使用的 **Python 后端**，不扩展 Go 上传链路。沿用 `POST /api/v1/datasets/{dataset_id}/documents` 的 multipart `file` 字段，支持 ZIP 与普通文件混传。页面的知识库上传组件不限制扩展名，已按接口返回的文档 ID 列表启动解析，因此无需新增页面、接口或任务表。

```text
原有登录与知识库权限校验
  → 本地上传入口
  → ZIP 检查、内存解包（普通文件原样传递）
  → Presidio 批量预处理（仅启用脱敏时）
  → 原有文件保存、文档登记和脱敏凭据发布
  → 返回子文档列表 → 原有解析、切片、索引任务
```

“入库”指文档上传登记；上传本身不等于切片索引完成。页面勾选上传后解析会使用全部子文档 ID；API 调用者仍调用原有解析接口。

## 2. 模块职责与低耦合设计

| 位置 | 改动与职责 |
| --- | --- |
| `common/zip_upload.py` | 一个独立预处理模块。只检查 ZIP、限制资源、读取成员并返回带 `filename/read()` 的内存文件。不访问数据库、对象存储、Presidio 或任务队列。 |
| `FileService.upload_document` | 在文件保存之前调用解包模块；启用脱敏时传入现有文件数量和大小限制，再调用原来的 `prepare_files`。复用原有保存与结果返回流程。 |
| `_upload_local_documents` | 将 ZIP 检查错误转为现有参数错误响应，不暴露压缩包成员名或内部异常。 |
| 原有 Presidio 核心、数据库、解析器、索引与前端 | 不增加 ZIP 专用逻辑，不复制识别规则，不新增依赖、表结构或后台任务。 |

文件格式通过调用方传入的原生 `filename_type` 检查，解包模块不维护第二份办公格式清单。只有本地知识库上传入口展开 ZIP；连接器、文件管理、远程 URL 和已有文档覆盖不借此新增支持。

## 3. 文件与目录规则

- 识别 `.zip`，扩展名不区分大小写；支持 ZIP Stored、Deflate。
- 遍历包内目录，忽略目录项。各文件按中央目录顺序上传到同一知识库，使用文件基本名，不创建包内目录结构；同名文件沿用 RAGFlow 自动改名规则。
- ZIP 中的相同相对路径（含大小写或 Unicode 规范化后重复）拒绝；不同目录下的同名文件不覆盖。
- 拒绝空包、仅含目录的包、损坏包、CRC 不符、加密包、嵌套 ZIP、不支持的压缩方式、符号链接及特殊文件。
- 拒绝绝对路径、`..`、`.`、空路径分量、盘符、冒号、NUL 和控制字符，限制文件名与目录深度。只在内存读取成员，不调用 `extract/extractall`，不将成员路径拼接为磁盘路径。
- 普通模式接受原生识别的文件类型；脱敏模式仍仅接受 UTF-8 TXT、Markdown、CSV，沿用字符数、CSV 形状和输出限制。PDF、Office 不因套上 ZIP 而绕过脱敏限制。
- 不存 ZIP 原包。普通模式保留子文件基本名；脱敏模式沿用匿名文件名，不保存包名、原始成员路径或未脱敏内容。

## 4. 资源限制

| 限制 | 普通模式 | 脱敏模式 |
| --- | --- | --- |
| 单个 ZIP 压缩体积 | 20 MiB | 同时受原有 12 MiB HTTP 请求上限约束 |
| 解包后文件数（含同批普通文件） | 100 | 5，复用现有脱敏限制 |
| 单个 ZIP 成员大小 | 20 MiB | 2 MiB，复用现有脱敏限制 |
| 本次请求 ZIP 成员解压总量 | 100 MiB | 10 MiB |
| 压缩比 | 最大 200 倍；既检查声明大小，也限制实际读取量 | 相同 |
| 中央目录条目数（含目录） | 每个 ZIP 最多 1,000 | 相同 |
| 成员路径 | 最多 16 层、1,024 字符；文件基本名 UTF-8 最多 255 字节 | 相同 |
| 同进程解包并发 | 最多 2；超出立即返回繁忙 | 相同 |

没有 ZIP 的请求不受新增 ZIP 限额影响。ZIP 总量限制针对解包成员，混传普通文件仍遵守原有上传或脱敏检查。原始 multipart 文件的框架级临时缓冲沿用现状，不承诺 HTTP 接收阶段绝不写临时文件；本模块不额外落盘原包或未脱敏成员。

## 5. 失败与重试

先完成所有 ZIP 的解包及检查，再进行 Presidio 批量预处理，最后才进入原有保存循环。包内任一危险、损坏、不支持或超限成员会使本次请求预处理失败，包含同批普通文件在内均不写入业务数据库或对象存储，不静默跳过。

保存阶段保持原来的逐文件事务和部分成功语义；对象存储与数据库不是整批分布式事务。接口返回成功的子文档和错误，重试整个 ZIP 可能生成重复文档，调用者应核对成功列表再重试。脱敏模式的错误不回显原始文件名。

ZIP 错误使用固定 `ZIP_*` 消息，不拼接成员路径、原文或底层异常；HTTP 响应沿用原生格式，参数错误为 JSON `code: 101`，HTTP 状态为 200。脱敏错误仍使用原来的 `REDACTION_*` 消息和 HTTP 400。压缩包不能影响知识库、租户、文档 ID、规则版本或解析参数。

## 6. 验证范围

1. 普通 ZIP、多目录、中文名、大写扩展名、混传、多包及同名成员：逐个文档保存，响应包含全部子文档。
2. ZIP 内 TXT/Markdown/CSV：真实 Presidio 识别与替换，数据库、对象内容和凭据不含测试敏感值，凭据校验通过。
3. 路径穿越、链接、加密、嵌套、坏 CRC、截断、重复路径、压缩比、数量和体积超限：拒绝且无业务写入。
4. ZIP 中一个成员脱敏失败、损坏或格式不支持：整批预处理失败，无原文保存；脱敏关闭后普通上传保持原有行为。
5. 本地 HTTP multipart → 原有上传函数 → SQLite 文档记录与文件存储的集成验证；明确与完整 MySQL/MinIO/解析 worker 部署的差异。
6. 回归现有全部脱敏测试；检查代码、格式、提交范围后，ZIP 功能单独形成一个提交。

## 7. 本地验证结果

2026-09-29，在 Windows 本地 Python 3.13.12、真实 Presidio 2.2.364 环境验证：**165 项通过**，含原有 109 项回归及新增 56 项 ZIP 测试。Ruff 检查、修改文件格式检查及 `git diff --check` 均通过。

| 实际验证 | 结果 |
| --- | --- |
| 普通 ZIP 经本机真实 HTTP 上传 | 3 个成员返回 3 个独立文档 ID；SQLite 中 3 条文档，磁盘 3 个文件；同名文件为 `report.txt`、`report(1).txt`，内容保持原样。 |
| 脱敏 ZIP 经本机真实 HTTP 上传 | 3 个成员分别处理手机号、邮箱、业务词，磁盘均为替换后的内容；3 条签名凭据逐一校验通过，原 ZIP 未保存。 |
| 未登录、无知识库权限 | 在文件入库前拒绝。HTTP 测试使用真实登录校验装饰器，身份查询及团队授权数据使用测试替身。 |
| 同批普通文件加危险 ZIP | 返回 `code: 101 / ZIP_UNSAFE_PATH`；文档数和磁盘文件数均不增加。 |
| 任一成员格式或 UTF-8 不符、超过数量/大小限制 | 整批预处理拒绝，不保存普通文件、ZIP 子文件或脱敏凭据。 |
| 路径穿越、NUL、符号链接/特殊文件、加密、嵌套、重复路径、CRC 损坏、截断、伪造大小、压缩比超限 | 拒绝；错误只含固定消息。 |
| 两个文件在保存阶段第二个失败 | 第一个文档及凭据保留，响应只返回成功文档及固定失败消息，保持现有部分成功语义。 |

HTTP 用例启动本机随机端口的 Quart/Hypercorn 服务，以 multipart 上传真实 ZIP，执行当前源码中的上传路由、文件服务、结果映射、Presidio 和凭据校验。SQLite 替代 MySQL，临时目录替代 MinIO；为避开 OCR/模型启动依赖，按现有测试方式直接加载生产函数，未运行完整 RAGFlow API 启动流程。

本轮没有部署到 237，也没有新增完整浏览器、MySQL/MinIO、worker 解析及向量检索验收；因此结论是 **ZIP 上传登记与入库前脱敏链路在本地集成验证通过**，不将这些结果写成全套部署已验收。

## 8. 使用方法

在知识库页面选择“上传文件”，选择 ZIP，可同时选择普通文件；按需要勾选上传后解析。成功后列表展示解包后的子文档。API 示例：

```bash
curl -X POST "$RAGFLOW_BASE_URL/api/v1/datasets/$DATASET_ID/documents" \
  -H "Authorization: Bearer $RAGFLOW_API_KEY" \
  -F "file=@资料.zip"
```

ZIP 没有额外开关。普通模式无需 Presidio 依赖；逐文件脱敏沿用既有 `RAGFLOW_REDACTION_ENABLED=1`、隔离实例、策略文件及签名密钥配置，详见[入库前脱敏实现与验证](入库前脱敏实现与验证.md)。
